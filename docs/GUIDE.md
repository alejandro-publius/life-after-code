# Judge guide

No install needed for a first look: the [five gallery images](images/gallery/) walk one demo night in order (she signs, an order is declined and she is woken, an order runs while she sleeps, the morning countersign, the refusals). The same demo runs in the browser on GitLab Pages once the project is public, or [locally](../README.md#try-one-night-in-the-browser): sign the demo orders, approve the fallback, review the automatic checkout change and read the morning brief, then replay without signing. The two paths make the human boundary visible.

This is a **local guided replay** with a simulated shop, planted faults and recorded model replies. The existing Watch code makes the decisions and writes the ledger. The controls choose isolated demo inputs. Live GitLab Duo execution, GitLab pipeline history and Google Cloud deployment are pending. See [Status](STATUS.md).

The [official rules](https://gitlab-transcend.devpost.com/rules) name five equally weighted criteria, so each has **20%** of the score before any cloud bonus. The primary-source extracts are in [Rules check](codex/RULES_CHECK.md#judging-stages-criteria-and-weights).

| Criterion | What to inspect | What the evidence establishes |
|---|---|---|
| Technological Implementation, 20% | [The nine stages, file by file](../README.md#life-after-code-stage-by-stage), [Watch](../relay/nightorders/watch.py), [decision checks](../relay/nightorders/decide.py), [GitLab ports](../relay/nightorders/gitlab_ports.py), [tests](../tests/), [Duo flows](../flows/), [Duo Code Review rules](../.gitlab/duo/mr-review-instructions.yaml), [pipeline configuration](../.gitlab-ci.yml) and the [refusal gallery](REFUSALS.md) (23 attempts, 0 production changes, a control that acts) | The relay works through GitLab itself: feature flags, incidents with timeline events, merge request merges and approvals as signatures, thumbs-up reactions as approvals, the deployments API that ends a kept change, and the Duo workflows API that starts the watch and dawn flows. The pipeline covers all nine stages, from tests and scans to the registry, Pages and a tagged release. A live Duo run and visible GitLab pipeline history remain required proof ([LIVE_GATES.md](LIVE_GATES.md)). |
| Design, 20% | The browser's Before bed, During the night and Over coffee chapters; unsigned and decline branches | A coherent human workflow from granting permission to reviewing its consequences. The default night needs one wake-up; an unsigned night grants no automatic authority. |
| Potential Impact, 20% | The on-call problem in the [README](../README.md), the wake-up messages and morning counts, and [how another team adopts it](ADOPT.md) | A specific audience and a demonstrated mechanism for handling a pre-approved reversible fault. Counts are demo results, with no measured production or sleep benefit. |
| Innovation/Idea, 20% | [What is new here](DEVPOST.md#what-is-new-here), [order validation](../relay/nightorders/orders.py), [orders](../demo/night-2026-10-20/orders.yml), [morning countersign](../relay/nightorders/countersign.py), [kept changes](../relay/nightorders/kept.py) | Automatic remediation is not new: rules that roll back or run a runbook when an alert fires are standing permissions, written once and kept until someone removes them. Night Orders makes the permission nightly: drafted from that day's merges, checked before she signs, void at 07:00, and narrowed, never widened, by the agent. Each morning she decides what stays, and a kept change ends when its fix is deployed. |
| Presentation, 20% | The [gallery](images/gallery/), [local phone screenshot](images/demo-phone.png), [local laptop screenshot](images/demo-laptop.png), [video script](VIDEO.md) and [English Devpost draft](DEVPOST.md) | A readable demo and narrative, with a captioned recording of the demo ready to upload (`scripts/record_demo.py`). The public YouTube link and the public demo URL are pending. |
