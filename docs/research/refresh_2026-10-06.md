## 2. GitLab Duo Agent Platform

Sources: [platform overview](https://docs.gitlab.com/user/duo_agent_platform/), [custom flows](https://docs.gitlab.com/user/duo_agent_platform/flows/custom/), [flow schema](https://docs.gitlab.com/user/duo_agent_platform/flows/custom_flows_schema/), [triggers](https://docs.gitlab.com/user/duo_agent_platform/triggers/), [Flows API](https://docs.gitlab.com/api/duo_agent_platform_flows/), [sessions](https://docs.gitlab.com/user/duo_agent_platform/sessions/), [composite identity](https://docs.gitlab.com/user/duo_agent_platform/composite_identity/), [external agents](https://docs.gitlab.com/user/duo_agent_platform/agents/external/), [execution variables](https://docs.gitlab.com/user/duo_agent_platform/flows/execution/execution-variables/), [tools](https://docs.gitlab.com/user/duo_agent_platform/agents/tools/), [flow registry v1 spec](https://gitlab.com/gitlab-org/modelops/applied-ml/code-suggestions/ai-assist/-/raw/main/docs/flow_registry/v1.md).

What is documented:

- **Custom flows** are generally available. Components: AgentComponent, OneOffComponent, DeterministicStepComponent, HumanInputComponent, with routers. Creating or enabling a flow needs Maintainer or Owner; running one needs Developer.
- **Triggers** (Premium or Ultimate; Maintainer to create): Mention, Assign, Assign reviewer, Pipeline events, Merge request (Approved, Created, Marked ready, Merge conflict), Work item (Created, Status changed). Only a human action fires a trigger. No schedule trigger, webhook trigger or flow-to-flow chaining is documented.
- **Flows API** (`POST /api/v4/ai/duo_workflows/workflows`) is generally available. It lets outside code start a flow with an access token. Whether a Developer account in the hackathon group gets a successful start is untested.
- **Human checkpoints**: a HumanInputComponent pauses the session, creates a To-Do and an email, and accepts Approve, Reject or Modify. Its documented outputs are the conversation history and `context:<name>.approval`.
- **Identity**: a flow acts with at most Developer rights. Merge requests a flow creates are attributed to the person who triggered it, and by default an author cannot approve their own merge request.
- **Token scope**: flow tokens are limited to the `ai_workflows` and `mcp` scopes. The Issues, Notes, Merge requests, Commits and Files APIs accept that scope; the Feature flags, Deployments and Environments APIs do not (read from GitLab's source, so this is an inference about runtime behaviour).
- **Execution**: flows run on CI runners, receive no custom CI/CD variables, and by default reach only the GitLab instance on the network.
- **External agents**: GitLab-managed Claude Code and Codex agents are generally available on Premium and Ultimate, behind a flag for verified customers, enabled by a Maintainer. Custom external agents cannot be created on GitLab.com. They are listed as a Duo Agent Platform feature.
- **Evidence**: sessions have a web page, are visible to Developer and above, and are deleted 30 days after last activity. Keep evidence in issues, notes, merge requests and pipelines as well.
- **Already shipped by GitLab** (AI Catalog, GitLab-maintained): Fix CI/CD Pipeline, Resolve SAST Vulnerability, SAST and secret false-positive checks, Resolve Dependency Bump Breaking Changes, Code Review, Security Review, Risk Assessment, Recommend Reviewers, Developer.

Where the existing repo assumes more than the docs:

- `flows/dusk.yml` and `flows/dawn.yml` ask the agent to read deployments and feature flags through `gitlab_api_get`. Those APIs likely refuse a flow token. Code must put that evidence in an issue or note.
- `flows/dusk.yml` reads `context:ask_oncall.response`, which is not a documented output.
- `docs/research/gitlab_guide_and_reference.md` recommends AgentComponent keys (`max_cycles` and others) that GitLab's schema rejects.
- Signing by merge needs Maintainer on a protected default branch, and the approval fallback fails by default when the signer also triggered the flow.

## 3. GitLab platform for a Developer-role builder

Sources: [stages](https://about.gitlab.com/topics/devops/), [environments](https://docs.gitlab.com/ci/environments/), [releases](https://docs.gitlab.com/user/project/releases/), [feature flags](https://docs.gitlab.com/operations/feature_flags/), [incidents](https://docs.gitlab.com/operations/incident_management/), [application security](https://docs.gitlab.com/user/application_security/), [webhooks](https://docs.gitlab.com/user/project/integrations/webhooks/), [permissions](https://docs.gitlab.com/user/permissions/), [CI job token](https://docs.gitlab.com/ci/jobs/ci_job_token/).

- **Stages**: the old stages page now redirects to the platform page. The public nine-stage list is on the DevOps topics page: Plan, Create, Verify, Package, Secure, Release, Configure, Monitor, Govern. Use it for Most Stages Covered.
- **Likely available to a Developer**: branch pipelines, job-level `id_tokens` for keyless Google Cloud, environments, deployments, review apps, feature flags, incidents through the Issues API, pipeline schedules, approving others' merge requests, SAST and secret detection templates. Releases are uncertain (the docs disagree on Developer versus Maintainer).
- **Needs Maintainer**: webhooks, project CI/CD variables (so no secrets in settings), trigger tokens, alert endpoints, protected environments, deployment approvals, deploy freezes, approval rules, project access tokens, enabling external agents, creating flow triggers. On-call schedules and escalation policies also need Premium.
- **CI job token** cannot post notes, open merge requests or use the Issues API.

## 5. Cloud and sustainability, for later

- **Cloud Run** ([pricing](https://cloud.google.com/run/pricing)): request-based billing scales to zero; the monthly free allowance is roughly $5 of compute; one idle minimum instance (1 vCPU, 512 MiB) is about $10 a month before the free allowance; builds, registry storage and logging are billed separately. New accounts get $300 for 90 days. Budget alerts do not cap spend.
- **Keyless deploy** ([Workload Identity Federation with deployment pipelines](https://cloud.google.com/iam/docs/workload-identity-federation-with-deployment-pipelines)): Google documents GitLab directly (issuer `https://gitlab.com`, condition on `namespace_id`).
- **SCI** ([GSF specification](https://sci.greensoftware.foundation/), ISO/IEC 21031:2024): SCI = ((E x I) + M) per R. Tokens, dollars or minutes are not carbon. Google's "Low CO2" label reflects purchased clean energy and is not a valid location-based I. No public per-token energy figure for Claude was found. We do not target the environmental prize.
