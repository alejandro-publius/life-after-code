## 1. LORE. Grand Prize, $15,000. Deep-dived: no (repo read in full; Devpost page and video not reached)

- **Links:** repo [35153311](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/35153311) (project name "doshikaran"). AI Catalog items: flow 1005843 and 1006466, agents 1006465 (LORE Ask) and 1007030 (LORE Migrate) ([.ai-catalog-mapping.json](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/35153311/-/blob/main/.ai-catalog-mapping.json)). Devpost URL not found.
- **Post wording (search excerpt):** "LORE uses eight agents with a router that sends each question to the right agent, logic to prevent circular loops in the knowledge graph, a visual dashboard, and carbon tracking." Another excerpt: "a system designed to combat knowledge loss when senior engineers depart" ([winners post](https://about.gitlab.com/blog/gitlab-ai-hackathon-2026-meet-the-winners/)).
- **What it does:** README pitch: "Most AI coding tools help you write code faster. LORE prevents you from writing the wrong code in the first place." It stores team decisions as wiki pages (`LORE-INDEX`, `LORE-MEMORY-001` and so on). On a new issue it writes a "pre-mortem" (past failures, predicted failures, a spec). On an open MR it posts a five-layer review: memory conflicts, "promise verification" against what the developer said in the issue, a security sentinel, code intelligence, and enforcement of past reviewer rules. After a merge it extracts new decisions. It also does health audits, onboarding briefings, Q&A ("LORE Ask") and a cold-start import from past MRs ("LORE Migrate") ([README](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/35153311/-/blob/main/README.md)).
- **GitLab Duo Agent Platform use (deep):** one public flow with 8 `AgentComponent`s: a `triage_router` with read-only tools that outputs `ROUTE: <agent_name>`, plus 7 worker agents, each routed to `end` ([flows/flow.yml](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/35153311/-/blob/main/flows/flow.yml)); a longer 1,908-line version with full prompts in [.gitlab/duo/flows/lore.yaml](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/35153311/-/blob/main/.gitlab/duo/flows/lore.yaml). Two public chat agents ([agents/](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/35153311/-/tree/main/agents)). Triggers: setup says "enable: Pipeline, Assign, Mention, Reviewer". Tools include MR diffs and notes, issues, wiki read and search, `gitlab_api_get`. No MCP or skills found. The flow ran at least 24 times in this repo (Mar 23 to 25), all successful ([pipelines](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/35153311/-/pipelines), `refs/workloads/*`, read via API).
- **Sponsor tools:** Claude through GitLab Duo (no model set in the YAML; the README has a whole "Why Anthropic Claude?" section). An older version in `legacy/` called the Anthropic SDK directly ([legacy/core/claude_client.py](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/35153311/-/blob/main/legacy/core/claude_client.py)). No Google Cloud.
- **Code beyond prompts:** a Python CLI (`lore validate`, `stats`, `sync`, `dashboard`) with DFS cycle detection and carbon math. I counted 43 test functions (8 + 18 + 17) in [lore-cli/tests](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/35153311/-/tree/main/lore-cli/tests). CI: YAML lint plus a 64 KiB catalog size check, pytest, catalog sync on tags, wiki sync, and a GitLab Pages dashboard built from `examples/sample-memories.txt` ([.gitlab-ci.yml](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/35153311/-/blob/main/.gitlab-ci.yml)).
- **Autonomy:** acts alone on low-risk writes (comments, issues, wiki memory). It never blocks: "LORE doesn't block the merge. But it doesn't forget you saw the warning." The developer replies `lore: intentional`, `lore: accidental` or `lore: discuss` ([README](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/35153311/-/blob/main/README.md)).
- **Demo style:** ran on real issues and MRs in its own repo (issues 2 to 9 and MRs 3 to 11, Mar 21 to 25; [issue list via API](https://gitlab.com/api/v4/projects/80354625/issues?state=all)). Example: issue 9 was opened by the flow's bot account: "LORE - Your institutional memory is at risk", flagging that MR 9 shipped exponential backoff that "Memory #002" had rejected ([work item 9](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/35153311/-/work_items/9)). Video: not reached (no link in the repo).
- **Human story:** "Teams don't break architecture because they're careless. They break it because: The people who understood the original decisions leave" ([README](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/35153311/-/blob/main/README.md)). Persona: "LORE speak as a slightly haunted senior engineer who has seen things break."
- **Live URL:** none stated. A Pages job exists but its URL is not given (unverified).
- **Team:** two committers, Khushi Sidana (15 commits) and doshikaran (11) ([contributors API](https://gitlab.com/api/v4/projects/80354625/repository/contributors)). Devpost team list not seen.
- **README structure (277 lines):** pitch line; The Problem; How LORE Works (8 numbered lifecycle steps); The Python CLI; CI/CD Pipeline; Architecture; Carbon & Sustainability Tracking; Why Anthropic Claude?; Project Structure; Tech Stack; Setup; Memory Format; Built for the GitLab AI Hackathon 2026; License.
- **Why it most likely won (my reading):** a human problem anyone recognizes (knowledge leaves with people), covered across the whole lifecycle with event triggers instead of chat, real engineering under the prompts (43 tests, cycle checks), proof on real MRs, an explicit Claude story for a co-sponsor, and a carbon angle on top.

## 2. Gitdefender. Google Cloud Grand Prize, $10,000. Deep-dived: no (repo read; video script found in repo; Devpost and video not reached)

- **Links:** repo [35458144](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/35458144) (project "kavishwer2301"). Catalog: agent 1007025, flows 1007154 and 1007171 (read directly). Devpost text is kept in [DEVPOST.md](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/35458144/-/blob/main/DEVPOST.md) and the video narration in [SCRIPT.md](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/35458144/-/blob/main/SCRIPT.md).
- **Post wording (search excerpt):** "It works inside code review workflows, finding and fixing security issues. It spots the bug, writes the fix, and opens the code review. No developer needs to step in." **This does not match the repo.** The repo is about scoring MRs, and a human approves each step. Trust the repo.
- **What it does:** "A reputation scoring engine for open source merge requests. It helps maintainers cut through the noise of AI-generated slop MRs by scoring them with an online-learning ML model trained on real GitLab data" ([README](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/35458144/-/blob/main/README.md)). 58 features in 6 groups. An Adaptive Random Forest (River) "pre-trained on 896 real GitLab MRs" from "20 public GitLab repositories including gitlab-org/gitlab, inkscape, fdroid", learning from every merge or close ([DEVPOST.md](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/35458144/-/blob/main/DEVPOST.md)). SCRIPT.md says "50 recent MRs from the these 10 repos", so the two texts disagree.
- **GitLab Duo Agent Platform use (deep):** flow "Gitdefender Extract" chains 5 agents (code quality, AI fingerprints, description and commits, architectural fit, feature collector), each passing `final_answer` on ([flows/gitdefender-extract.yml](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/35458144/-/blob/main/flows/gitdefender-extract.yml)). Trigger: set the agent as MR reviewer (SCRIPT.md). It posts a review comment and stores the feature vector as an internal MR note prefixed `GITDEFENDER_FEATURES:`. An IDE chat agent picks that up and calls the scoring server with `run_command` + curl ([agents/agent.yml](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/35458144/-/blob/main/agents/agent.yml)). A third path, a custom flow config, runs a Python agent built on the Claude Agent SDK (`claude_agent_sdk`) against GitLab's AI Gateway Anthropic proxy with `injectGatewayToken: true` ([.gitlab/duo/flows/gitdefender.yaml](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/35458144/-/blob/main/.gitlab/duo/flows/gitdefender.yaml), [gitdefender/pr_agent.py](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/35458144/-/blob/main/gitdefender/pr_agent.py)). No MCP.
- **Google Cloud (deep):** FastAPI scoring server on Cloud Run (asia-southeast1), Cloud SQL Postgres, GCS for the model, Artifact Registry, all in Terraform ([terraform/main.tf](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/35458144/-/blob/main/terraform/main.tf)).
- **Platform limit turned into design:** "The biggest challenge was the network sandbox. All agents and flows running in GitLab's cloud cannot make outbound HTTP requests". So the cloud flow extracts features and the IDE agent calls the server "from the user's local machine" ([DEVPOST.md](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/35458144/-/blob/main/DEVPOST.md)).
- **Autonomy:** acts with approval. The flow posts on its own; the IDE agent asks "Ready to proceed?" before each phase (score, review, merge with conflict resolution, feedback). "The maintainer just keeps saying 'yes' to move to the next step."
- **Demo and video:** from [SCRIPT.md](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/35458144/-/blob/main/SCRIPT.md), the likely first 30 seconds: "You've probably seen the headlines - open source maintainers drowning in AI-generated slop MRs, burning out, GitHub even floating the idea of a PR kill switch. The problem isn't just the volume - it's that AI generates code that looks good but isn't correct." The demo creates an MR, sets the agent as reviewer, shows the comment, then the IDE agent scores it 0.44 and the model's "progressive accuracy sitting at 0.74". Length unknown; the script is about 370 words, roughly 2.5 to 3 minutes spoken (my estimate). Title not known (YouTube blocked).
- **Human story:** "open source maintainers getting bombarded with AI-generated MRs, with many of them overwhelmed by low-quality, automated, or irrelevant submissions, which are leading to high burnout rates" ([DEVPOST.md](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/35458144/-/blob/main/DEVPOST.md)).
- **Live URL:** `https://gitdefender-server-455397901143.asia-southeast1.run.app` in the agent prompt ([agents/agent.yml](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/35458144/-/blob/main/agents/agent.yml)). Not checked (proxy refused run.app).
- **Team:** solo. Commits by "kavish" (20) ([contributors API](https://gitlab.com/api/v4/projects/80562004/repository/contributors)); DEVPOST.md says "I".
- **README structure (127 lines):** How It Works (3 parts, 2 diagrams); Replicating the Scoring Server (step by step with env table and curl tests); Deploying to GCP; Feature Categories table; License.

## Patterns so far

1. **Event-triggered, writes back into GitLab.** All 8 react to a mention, a reviewer assignment, a merge or a pipeline, and leave their output in MR notes, issues or new MRs. None is chat-only, which matches the rule "Chat alone won't qualify" ([onboarding issue](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/621485/-/work_items/1)).
2. **Several narrow agents, not one big one.** LORE 8 (with a router), Time-Traveler 8, Aegis 7, Gitdefender 5, Launch Control 4 (5 tools each), DocSync 3, RedAgent 3. Hand-offs use `context:<agent>.final_answer`, sometimes with JSON schemas (DocSync).
3. **A human owns the risky step.** No winner merges or deploys without a yes: Time-Traveler's deployer asks first, DocSync never auto-merges, LORE never blocks, Launch Control only advises, Gitdefender asks "Ready to proceed?". Low-risk writes (comments, issues, branches) happen without asking.
4. **Real code and data under the prompts.** Tests (LORE 43, Aegis 56 claimed), ML models (Gitdefender on 896 real MRs; Aegis on synthetic data), deterministic scoring (Time-Traveler penalties, Launch Control policy YAML). Judges seem to have rewarded "not just a prompt".
5. **Sponsor fit was spelled out.** READMEs carry sections like "Why Anthropic Claude?", "Prize Tracks" and "Prizes Targeted". Google prize winners deployed real GCP (Cloud Run + Cloud SQL + Terraform; GKE + Vertex AI + BigQuery via Terraform). Anthropic prize winners ran Claude inside GitLab through the AI Gateway: Claude Code CLI as an external agent (GraphDev), an external `claude_agent` (Aegis); Gitdefender used the Claude Agent SDK.
6. **Platform limits became part of the story.** No outbound HTTP from cloud flows (Gitdefender split cloud and IDE; Time-Traveler used `run_command` + curl), no rights to register MCP servers (Time-Traveler's bridge).
7. **Demos on real MRs, linked from the README.** GraphDev MR 3, Launch Control MR 3, Time-Traveler MRs 7 and 8, LORE issues by its bot. Most embed a small demo app in the repo (DocSync, Time-Traveler, GraphDev, Aegis, RedAgent).
8. **About 3-minute videos that open on a felt pain.** Known lengths: Launch Control 179.8 s; BugFlow's README says "3-minute demo video". Openings: the 11pm migration, maintainer burnout, "shipped a release they shouldn't have".
9. **Green angle everywhere.** Carbon notes in LORE, Time-Traveler, Aegis and Launch Control, besides the separate $3,000 Green Agent prize and four $500 Sustainable Design bonuses.
10. **Mostly one builder.** 6 of 8 repos have one human committer; LORE and DocSync have two. Several solo builders still write "we".
11. **The submission text lives in the repo** (DEVPOST.md, SUBMISSION.md, SCRIPT.md, demo-script.md).
12. **Not everything was clean, and they still won:** unsourced statistics (73%, 50-70%), demo secrets committed (GraphDev API key, Time-Traveler bearer token), synthetic training data not labelled as such (Aegis), docs that disagree (Gitdefender 10 vs 20 repos; RedAgent Gemini vs Claude), README links to missing files (DocSync).
