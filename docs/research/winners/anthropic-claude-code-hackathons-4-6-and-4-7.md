# Anthropic Claude Code hackathons: Built with Opus 4.6 and Built with Opus 4.7

Compiled 2026-10-06 for Alex Velazquez (Life After Code, GitLab Transcend Hackathon). This file covers the two virtual Claude Code hackathons that Anthropic ran with Cerebral Valley in 2026: the facts of each event, all 11 winners, and what the judges rewarded.

How I gathered this:

- I read every page with WebFetch. WebFetch gives back a model-written summary of a page, not the raw text. I asked for exact quotes and checked the important ones a second time with a narrower question. A quote can still be off by a word.
- The official event pages on cerebralvalley.ai are blocked, so the rules, criteria and judges come from copies of the event page that winners saved in their own repos: [R46-PV] (PostVisit), [R46-CB] (CrossBeam), [R47] and [E47] (ARIA).
- Star, fork and commit counts are as of 2026-10-06.
- Where a quote had an em dash or en dash, I wrote " - " instead.
- "Why it most likely won" is my own inference, not something the judges said.

Problem statements [R46-PV]:

- Build a Tool That Should Exist: "Create the AI-native app or workflow you wish someone had already built. Eliminate busywork. Make hard things effortless."
- Break the Barriers: "Expert knowledge, essential tools, AI's benefits - take something powerful that's locked behind expertise, cost, language, or infrastructure and put it in everyone's hands."
- Amplify Human Judgment: "Build AI that makes researchers, professionals, and decision-makers dramatically more capable - without taking them out of the loop."

Judging criteria [R46-PV] (the CrossBeam copy gives the same four weights [R46-CB]):

- Demo, 30%: "Is this a working, impressive demo? Does it hold up live? Is it genuinely cool to watch?"
- Impact, 25%: "What's the real-world potential here? Who benefits, and how much does it matter? Could this actually become something people use? Does it fit into one of the problem statements?"
- Opus 4.6 Use, 25%: "How creatively did this team use Opus 4.6? Did they go beyond a basic integration? Did they surface capabilities that surprised even us?"

Special prizes [R46-PV]:

How judging worked [R46-PV]: in Stage 1, judges score each submission on their own against the four criteria. The top 6 go to Stage 2, where their pre-recorded 3-minute demos are played and the judges deliberate.

## Winner deep dives: Built with Opus 4.6

### CrossBeam (1st place)

Deep-dived: yes. Sources: post [P46], repo [CB], README [CB-README], build journal [CB-PROG].

- **What it does.** A permit assistant for California ADUs (backyard homes). You upload the architectural plans and the city's corrections letter. The agent reads every page, checks state ADU law and city codes, asks you clarifying questions, and returns an analysis report, a scope of work and a draft response letter [CB-README]. The post: "parallel sub-agents parse the documents, build a spatial index, and assign targeted agents to each discrete correction." and "Twenty minutes later, the builder has a precise action plan for approval." [P46]. A second flow writes permit checklists. A third flow, city pre-screening, is only a plan: "This flow is not built" [CB-README].
- **How Claude and Claude Code were used (deep).**
  - The agent runs on the Claude Agent SDK with Opus 4.6 and the `claude_code` preset, inside Vercel Sandbox, started by an Express server on Cloud Run. Supabase Realtime streams progress. The reason for this design: "Agent runs take 10-30 minutes. Vercel serverless functions timeout at 60-300s." [CB-README]
  - Skills come first: "The agent's domain knowledge comes from skills - structured reference files that teach Claude." The California ADU skill has 28 reference files and a decision-tree router [CB-README]. The repo has at least 16 skill folders, including adu-city-research, adu-corrections-interpreter, crossbeam-ops, demo-city-review, long-running-agent and product-demo-video [CB-SKILLS].
  - The build journal describes batch sub-agents that coordinate through files, plus a skill that teaches Claude Code agents to run the deployed site [CB-PROG].
  - Claude Code built the product: "Mike built CrossBeam using a workflow of prompting Claude Code and then having Claude create the tests." [P46]. The README lists "Claude Code (built entire project)" [CB-README]. Commit trailers credit Claude Opus 4.6, and some credit Cursor [CB-C1], [CB-C7].
  - No hooks or MCP config were visible.
- **Autonomy.** It drafts and a human acts. The agent asks the contractor questions and produces documents, and the contractor decides what to submit ("an action plan for approval" [P46]). The README does not describe a separate review gate [CB-README].
- **Human story.** "Everyone thinks California has a housing crisis. We don't. We have a permit crisis," and "I didn't write a single line of code," ... "I didn't even read a line of code." [P46]
  - The post names a real city: "Buena Park, a city in Southern California which needs to permit more than 8,900 housing units by 2029 but permitted only about 120 in 2024" [P46].
  - The journal says he interviewed the Mayor of Buena Park and a contractor for the video [CB-PROG]. ARIA's planning notes describe CrossBeam's video as "Mayor Connor on camera, real contractor Cameron" [AR-WIN] (video not opened).
- **Live URL.** www.crossbeam-permits.com, from the repo About field [CB]. Not opened.
- **Team size.** 1.
- **README structure.**
  - Headings in order: CrossBeam; Winner (Anthropic's Global Claude Code Hackathon "Built with Opus 4.6"); For Other Builders; Contact; The Problem; What CrossBeam Does (Flow 1: Corrections Letter Interpreter, Flow 2: Permit Checklist Generator, Flow 3: City Pre-Screening (Roadmap)); Architecture (Why this architecture, Skills-First Design); Tech Stack; Project Structure; Running Locally (Prerequisites, Frontend, Server); Test Data Attribution; License [CB].
  - No screenshots. An ASCII architecture diagram. A local quickstart. No demo link (the video is linked from the post).
  - "For Other Builders" points readers to the voice-log journal in progress.md [CB-README].
- **Specs and evals before code.**
  - The first commit (Feb 11, 2026) is "Initial commit - research, planning, and ADU skill foundation" [CB-C7].
  - docs/ holds spec.md, plans/, research/ and testing/. testing/ includes test-skill-aduHandbook-0210.md, dated by file name to Feb 10 [CB-DOCS], [CB-TEST].
  - The journal records accuracy tests on plan extraction: about 85% in 10 to 15 minutes against 95% in 35 minutes per plan set. That result drove a pivot to "Figure out what matters first, then go look for it". Long plans (plan-deploy.md, 756 lines) were written before the deploy sprint [CB-PROG].
  - There is no automated eval suite in the README.
- **Demo built for judges.**
  - The app had three modes: Dev Test, Judge Demo and Real. On submission day he added a "Showcase" button (instant results) and a "Run Live" button (watch the agent work), because the Judge Demo skipped the agent run [CB-PROG].
  - A commit on Feb 16: "Point back link to dashboard so judges return to persona cards" [CB-C1].
- **Repo stats.** 69 commits from Feb 11 to Mar 2, 2026. 293 stars, 96 forks. MIT license [CB], [CB-C1], [CB-C7].
- **Why it most likely won (inference).** A costly real problem with hard numbers and a named city. A deployed agent that judges could run live. Deep use of the Agent SDK, skills and sub-agents. A non-coder story that fits the series' message.

The blocks map to goals, requirements, skills, rules (hooks), portals (MCP servers, CLI, hardware), minions (agent roles), flow (task graph and human gates) and deploy targets. ### TARA ("Keep Thinking" Prize)

Deep-dived: yes. Sources: post [P46], repo [TA], README [TA-README], master plan [TA-PLAN], hooks [TA-SET].

- **What it does.** Turns dashcam video and GPS into a road investment appraisal. Opus 4.6 vision rates every frame (TMH12 and ASTM D6433 standards). The tool splits the road into sections, prices repairs, and runs cost-benefit analysis (NPV, EIRR, BCR, FYRR), sensitivity, deterioration and equity scoring. It ends with a PDF report [TA-README]. "This process used to take weeks. TARA does it in five hours." [P46]
- **How Claude and Claude Code were used (deep).**
  - In the product: Opus 4.6 vision, plus an agent loop with tool use (agent/orchestrator.py, tools.py, prompts.py) [TA-README].
  - Claude Code: "Built with Claude Code - Multi-agent development with hooks for autonomous operation" [TA-README]. .claude/settings.json defines these hooks [TA-SET]:
    - SessionStart shows git status and open TODOs.
    - PermissionRequest auto-approves common commands.
    - PreToolUse blocks rm -rf, git push, branch changes, merge, rebase and reset --hard.
    - Stop and SubagentStop run review prompts.
    - PreCompact backs up the transcript.

## What Anthropic judges rewarded

### What the official criteria say

Both events used the same four criteria: Impact, Demo, Opus Use, and Depth & Execution. In 4.6, Demo had the most weight (30%). In 4.7, Impact had the most weight (30%) and gained the line "Does it fit into one of the problem statements listed above?" [R46-PV], [R47]. The Opus criterion asks the same thing both times: "Did they go beyond a basic integration? Did they surface capabilities that surprised even us?" [R46-PV], [R47]

### What the winners posts say

Neither post explains the judges' choices [P46], [P47]. What the posts put first:

- Who the builder is, usually a domain expert rather than a developer ("four out of five winners were not professional developers" [P46]).
- The real problem, with numbers.
- Real users or pilots.
- How the builder worked: specs first, evals, planning, and asking Claude to review.

### Patterns across the 11 winners (my counts, from the sections above)

1. **Solo builders won 10 of 11 prizes.** Only ARIA had two people [P46], [P47].
2. **9 of 11 came from the builder's own work, family or community.** That includes all six top-3 places. The exceptions are the two creative-prize winners (Conductr, Virtual Puppet Theater), which are play and music projects.
3. **10 of 11 have a named human story in the post.** A daughter (Elisa), a son (Virtual Puppet Theater), a father (MaestrIA), a veteran technician (ARIA), a city that permitted about 120 homes in a year (CrossBeam), a doctor alone in an ER (Medkit), patients after they leave the room (PostVisit), a self-taught repair technician (Wrench Board), students who cannot read their own code (Maieutic), and a road under construction in Uganda (TARA). Conductr is the exception: its story is about craft.
4. **Planning before the main build is documented for 8 of 11, by commit dates or in the post.** CrossBeam, Elisa, PostVisit, TARA, Conductr, Maieutic, MaestrIA, and ARIA (after a day-1 scaffold). Medkit and Virtual Puppet Theater have spec documents, but their timing cannot be checked. Wrench Board was prototyped in Claude Design first [P47].
5. **Every winner with a public repo shows tests. Measured evals are rarer.**
   - Tests: Elisa (1,500+ per the post), PostVisit (262), ARIA (200+), Medkit (52 plus a verify loop), TARA (a 12-check validator), Conductr (C unit tests), Virtual Puppet Theater (one sanity test).
   - Evals against ground truth or the real model: MaestrIA (9 dimensions, 12 cases, 74% to 81%), Wrench Board (a sourced, frozen benchmark), Maieutic (a test suite that calls the real model) and CrossBeam (extraction accuracy runs).
   - One winner said the eval should be the first commit next time: "If I did another hackathon, the eval would be the first commit." [P47]
6. **Demos were built for judges.**
   - CrossBeam added "Showcase" and "Run Live" buttons, a judge login and persona cards [CB-PROG], [CB-C1].
   - PostVisit ran a public demo with no login [PV-README]. TARA ships cached data, so judges need no API key [TA-README].
   - Medkit defined success as four beats in the video [MK-SPEC]. ARIA planned a `make demo` command that works in under 60 seconds and captions in the UI naming each Opus feature [AR-WIN].
   - Builder tip: "I'd reserve that entire last day just for producing the demo." [P47]
7. **The model does something only it can do, and it is easy to see.** Vision on plans, schematics, roads and photos (CrossBeam, Wrench Board, TARA, MaestrIA). 1M context and thinking budgets (PostVisit). Long-running hosted agents (Medkit, ARIA). Opus as a creative partner (Conductr, Virtual Puppet Theater). ARIA's win plan says eight Opus capabilities "ship invisibly" and mostly need only caption-level fixes (fetch-tool paraphrase) [AR-WIN].
8. **A human stays in control of anything that matters.**
   - The 4.6 event had a whole track called "Amplify Human Judgment" [R46-PV].
   - Product patterns:
     - Medkit: "auto-allow reads, confirm writes" [MK-SPEC].
     - Elisa: "check with me" gates [EL-README].
     - Wrench Board: every part name comes from a tool lookup, and the technician measures [WB-README].
     - PostVisit: "Doctor-in-the-loop design" [PV-README].
     - MaestrIA: drafts the WhatsApp message, and the user sends it [P47].
   - Build-time patterns:
     - TARA: hooks block git push and destructive git [TA-SET].
     - Wrench Board: "Never `git push` without explicit authorization" [WB-CLAUDE].
     - Virtual Puppet Theater: "Never deploy unless explicitly requested." [VPT-CLAUDE]
9. **Builders treated Claude as a reviewer and planner, not only a typist.**
   - "Think before you build." (Maieutic)
   - "Ask Claude to find if there's anything wrong with what you've already built before building the next thing," (ARIA)
   - "Go deep in the brainstorm and push back on the model." (Wrench Board)
   - "not just a code generator, but a thought partner" (Medkit) [P47]
10. **Winners studied the rules and the past winners.** Four winners map the judging criteria directly in their repo docs: TARA's master plan [TA-PLAN], PostVisit's rules notes [R46-PV], Medkit's "What wins prizes here" [MK-SPEC], and ARIA's PRD and win plan [AR-PRD], [AR-WIN]. ARIA benchmarked itself against CrossBeam [AR-WIN].

### What this suggests for Life After Code (inference, for an Anthropic judge on the panel)

- Lead with one real person in the post-code lifecycle, such as the on-call engineer, and with a problem Alex has lived. 9 of 11 winners built from their own work, family or community.
- Commit a dated spec and an eval before product code, and show the eval moving. MaestrIA's 74% to 81% line is the kind of number the post chose to print.
- Map each judging criterion to something visible on the README's first screen and in the video, as Medkit and ARIA did.
- Give judges a live path and a cached path, plus one command to run it. CrossBeam's "Run Live" and TARA's cached data both avoided a demo that fails.
- Show the model doing work only it can do, and label it in the UI.
- Keep "auto-allow reads, confirm writes" as the human-control rule. It matches AGENTS.md rule 4 and the 4.6 "Amplify Human Judgment" track.
- Solo is not a handicap here: 10 of 11 winners were solo.
