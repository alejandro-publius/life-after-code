## 10. BugFlow (Sustainable Design bonus)

**Deep-dived: no.** Repo read in full. Devpost page not opened (blocked). Video link found in the README but YouTube is blocked, so the title and real length are unverified.

- **Repo:** [2026-02-ai-hackathon/34708497](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/34708497) ([README](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/34708497/-/blob/main/README.md)).
- **Winners post:** "BugFlow turned one bug report into 10 fixes in 20 minutes." ([winners post](https://about.gitlab.com/blog/gitlab-ai-hackathon-2026-meet-the-winners/), search excerpt)
- **What it does:** you @mention it on a bug issue. Four agents run in sequence. Detective finds the merge request that introduced the bug. Hunter scans every file that MR changed for "sibling bugs" and files a new issue for each one, after checking the last 30 issues to avoid duplicates. Fixer writes minimal fixes for all of them in one MR. Guardian writes regression tests in a second MR. A separate "Green CI Optimizer" flow rewrites a wasteful `.gitlab-ci.yml` into an MR (path rules, caching, `interruptible`). README tagline: "**Report one bug. Get nine fixes, forty tests, and a faster pipeline.**"
- **Duo Agent Platform use (deep):** two flows and three standalone agents in the catalog: "BugFlow - The Regression Detective" (v1.2.0), "BugFlow Green CI Optimizer", and agents Detective, Hunter, Guardian ([flows/bugflow.yml](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/34708497/-/blob/main/flows/bugflow.yml), [flows/optimizer.yml](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/34708497/-/blob/main/flows/optimizer.yml), GraphQL `aiCatalogItems`). Each component has its own toolset (9 to 11 tools, for example `gitlab_merge_request_search`, `get_commit_diff`, `create_issue`, `create_commit`, `create_merge_request`) and a 600 s timeout. Agents pass structured fields through issue comments (`ROOT_CAUSE_MR`, `VERDICT: PROCEED` or `HALT`, `HUNTER_VERDICT`), with re-run protection and branch-name fallbacks.
- **Other sponsor tools:** Claude through GitLab Duo ("Powers all 5 agents through GitLab's integrated AI", README). No Google Cloud.
- **Autonomy:** acts alone up to the merge request. It creates issues, branches, commits and two MRs; a human merges. It can stop itself: "If the issue isn't a code bug or root cause is unclear → `VERDICT: HALT`" (README). The README also oversells a little: "~20 minutes, zero human effort".
- **Evidence it ran:** 53 of the project's 69 issues were opened by the flow's service account, and 42 commits come from the two flow accounts ([issues](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/34708497/-/issues), [commits](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/34708497/-/commits/main)). Merge requests show many full runs on Python, JavaScript and Go demo code, for example "BugFlow: Fix 10 critical bugs from MR !13 validation removal" ([MRs](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/34708497/-/merge_requests?scope=all&state=all)). The author planted the regressions himself through "refactor: simplify ..." MRs, then filed bug reports.
- **Demo style and video:** README walkthrough with 7 screenshots, a before/after table, a sustainability table (docs-only pipeline "28 min" to "1 min"), and "📹 **[Watch the 3-minute demo video](https://youtu.be/Ae6xQecySV8)**". The README lists the video's six beats: one bug on a Go codebase with Chinese comments, Detective, Hunter finds 8 siblings, Fixer, Guardian writes 40 tests, Optimizer. Length "3-minute" is the README's claim (unverified).
- **Human or emotional story:** a business-loss frame, not a named person: "*A real bug report from a customer support escalation - $847.50 in financial losses from over-refunds:*" (README, dash replaced). It is a demo scenario the author built. Also: "That's it. Walk away. BugFlow handles the rest."
- **Live URL:** none; it runs inside GitLab.
- **Team:** solo (Mohit Marvania); 108 commits across branches; work from Feb 18 to Mar 25, with the demo video added on Mar 25 ([commits](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/34708497/-/commits/main)).
- **README structure:** tagline, problem ("Iceberg Bugs", CI waste), solution, step-by-step walkthrough with screenshots, end-result table, Green CI Optimizer, "How Claude Powers BugFlow", languages tested, comparison with Copilot, CodeRabbit, Devin and Cursor, getting started, architecture, sustainability impact, **known limitations**, demo video, built with.
- **Small inconsistencies:** the tagline says nine fixes and forty tests, the screenshot captions say 10 bugs and 63 tests, and the winners post says 10 fixes.
- **Why it most likely won (my reading):** a new idea in one sentence (one bug report leads to its hidden siblings), shown with real runs that judges could click through in the issue list. The second flow turns the same work into a measured cut in CI compute, which is what the Sustainable Design bonus asks for.

## 11. DELTA Cyber Reasoning System (repo: Delta CRS) (Sustainable Design bonus)

**Deep-dived: no.** Repo read in full, including `PROJECT.md`, which has Devpost's section headings and is most likely the Devpost write-up (unverified). Devpost page and video not opened. No video link in the repo.

- **Repo:** [2026-02-ai-hackathon/35701012](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/35701012) ([README](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/35701012/-/blob/main/README.md), [PROJECT.md](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/35701012/-/blob/main/PROJECT.md)). A GitHub mirror named in the commit messages (github.com/LeeSinLiang/delta-crs) returns 404.
- **Winners post:** "DELTA Cyber Reasoning is automated fuzz testing for security", which "analyzes diffs, generates fuzz harness, run the fuzzer, triage, and submit patches with report in one duo flow." ([winners post](https://about.gitlab.com/blog/gitlab-ai-hackathon-2026-meet-the-winners/), search excerpt)
- **What it does:** assign it as a reviewer on a C/C++ merge request. It reads the diff, writes a libFuzzer harness for the changed functions, compiles it with clang and AddressSanitizer (fixing compile errors up to 3 times), fuzzes for 60 s, reproduces crashes, commits patches to the MR branch, files vulnerability issues and posts a report ([flow](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/35701012/-/blob/main/flows/delta-crs-flow.yml)).
- **Duo Agent Platform use (deep):** a 3-step flow (analyze, fuzz, report) with scoped toolsets of 10, 5 and 7 tools, including `run_command`, `create_commit`, `post_duo_code_review` and `create_vulnerability_issue`. Timeouts are 180/300/120 s. It triggers on MR events and review requests, and `agent-config.yml` installs clang in a `setup_script` ([agent-config.yml](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/35701012/-/blob/main/.gitlab/duo/agent-config.yml)). The catalog shows the flow at v1.10.0. The commit log shows how they got it working: "fix: consolidate flow to single component with short prompt (27KB→2KB)" and "fix: use consistent mapped input format in all flow components (fixes WebSocket closure)" ([commits](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/35701012/-/commits/main)). The README still claims a "650+ line system prompt"; the current agent file has a 66-line prompt and 21 tools, and the long version survives as `flows/delta-crs-flow.yml.full` (777 lines).
- **Other sponsor tools:** Claude through Duo for the flow. A separate Python pipeline (12 modules) calls the Anthropic API directly when `ANTHROPIC_API_KEY` is set, for six tasks, including a multi-turn ReAct patcher. With no key, CI falls back to deterministic fuzzing ([.gitlab-ci.yml](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/35701012/-/blob/main/.gitlab-ci.yml)). No Google Cloud.
- **Autonomy:** acts alone on the MR branch and commits fixes; a human merges. README: "The developer reviews the auto-committed fix and merges - no context switching." (dash replaced). PROJECT.md: "The system works end-to-end with zero human intervention: from MR diff to posted report".
- **Evidence it ran:** 6 commits by the "Delta CRS" service account fixing named CWEs on test branches, for example "fix: prevent stack buffer overflow in http_log_request (CWE-787)", and 13 `test/vuln-*` branches ([commits](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/35701012/-/commits/main)). 27 unit tests ([tests](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/35701012/-/blob/main/tests/test_components.py)).
- **Demo style and video:** an interactive Svelte slide deck with a simulated fuzzer ("Click 'Run Fuzzer' to start"), built for Cloudflare Workers ([presentation](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/35701012/-/tree/main/presentation)); its URL was removed from the repo ("fix: remove URL"). There is also `./demo.sh quick` for a 5-minute local Docker run. Video unknown.
- **Human or emotional story:** none named. Problem-first framing: "Security bugs are the most expensive to fix in production." The slides add "70% of security vulnerabilities in C/C++ are memory safety bugs. They cost $4.88M per breach on average."
- **Live URL:** none in the repo (removed).
- **Team:** 2 (Sin Liang Lee and Isaac Hung). Commits on GitLab start on Mar 24 and run to Mar 25, about 30 hours; earlier work was most likely on GitHub (unverified).
- **README structure:** one-line problem, flow diagram, demo steps, flow architecture, "What Makes This Different" (research port from "Team Atlanta's Atlantis system (1st place, DARPA AIxCC 2025)"), Claude integration table, Duo platform use, quick start, demo target with 4 seeded CWEs, project structure.
- **Why it most likely won a Sustainable Design bonus (my reading):** the design spends the model only where it adds value. The analysis is scoped to the MR diff, a deterministic fallback runs with no LLM at all, triage is deterministic, and cross-run memory skips crashes it already knows. PROJECT.md says it outright: "Deterministic triage matters more than LLM triage." That matches the bonus wording about "model optimization techniques". It is also technically deep and proven by bot commits.

**Deep-dived: no.** Repo read in full. Devpost page and video not opened; no video link or screenshots in the repo.

- **Repo:** [2026-02-ai-hackathon/35504826](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/35504826) ([README](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/35504826/-/blob/main/README.md)).
- **Winners post:** "CarbonLint applied code analysis to energy use." - **What it does:** a Duo Chat agent ("CarbonLint Advisor") and an @mention flow ("CarbonLint Analyzer") audit `.gitlab-ci.yml` for five kinds of waste (redundant runs, heavy images, missing cache, artifact bloat, pipeline structure). They give a "Green CI Score" from 1 to 10 with a rubric, before/after YAML, time and CO2 estimates ("1 compute-minute ≈ 0.5g CO2"), and an org-wide projection. "Auto-Fix Mode" opens an MR with an optimized CI file and can add a README badge.
- **Duo Agent Platform use (moderate):** a chat agent with 25 tools ([agent.yml](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/35504826/-/blob/main/agents/agent.yml)) and a 2-component flow ([flow.yml](https://gitlab.com/gitlab-community/community-projects/2026-02-ai-hackathon/35504826/-/blob/main/flows/flow.yml)). Catalog versions: agent v1.3.0, flow v1.6.0. The README says the flow uses "25 tools across 2 agents" and validates with `ci_linter`. The final flow file is simpler: the scanner has 4 tools, the reporter has 3, and there is no `ci_linter`.

## Patterns

From the five winners above, compared with the sample and the field:

1. **Every environmental winner hooks into a moment GitLab already has.** A pipeline finishing (GreenPipe A), a bug issue (BugFlow), a review request (DELTA), a chat question or @mention (CarbonLint, GreenPipe B), a Terraform MR (TFGuardian). Results land as an MR comment, an issue or an MR. No winner needs you to open a separate app; TFGuardian's dashboard is extra.
2. **Proof is visible in GitLab itself.** Winners have commits, issues or MRs created by their own flow accounts: TFGuardian (64 of the last 100 commits), BugFlow (53 issues, 42 commits), DELTA (6 CWE-fix commits), GreenPipe B (8 commits), CarbonLint (an agent-made MR and issue). Most sampled non-winners show none. Judges could click and see the agent's work.
3. **A human stays at the merge.** All five stop at a comment, an MR or a verdict. CarbonLint asks for confirmation; TFGuardian marks risky changes REVIEW_REQUIRED; BugFlow can HALT itself. The loudest "zero human intervention" and "sentient" pitches in the sample won nothing. This matches the Life After Code rule that a human decides when the agent acts on anything that matters.
4. **Real tools and named standards decide what is true; the model chooses where to look.** tfsec, checkov, gitleaks, infracost, libFuzzer with ASan, `ci_linter`, `terraform validate`, the SCI standard and Cloud Carbon Footprint. DELTA moved crash triage from the LLM to fixed rules, and the bonus wording ("model optimization techniques") rewarded that kind of design.
5. **Numbers with a before and after.** "$556/mo → $21/mo", "28 min → 1 min", "SCI reduction: 58.2%", "4 seeded CWEs found and patched". The honest ones also give limits (GreenPipe A's "Limitations", BugFlow's "Known Limitations", Kassandra's 23 of 37 runs). Watch the trap: TFGuardian's 96% CO2 figure equals an example written into its own prompt. Under Alex's rules, such a number must be labelled as demo data.
6. **Time-boxed agent loops were normal.** Each step had a 120 to 600 s timeout, and the prompts cap retries at 3 ("Do NOT repeat a step more than 3 times"). DELTA had to cut its prompt from 27 KB to 2 KB before its flow stopped failing.
7. **Solo builders won.** BugFlow, CarbonLint, TFGuardian and GreenPipe B are one person each; DELTA is two. CarbonLint and DELTA were mostly built in the last 2 to 6 days, so a focused late build can still win a bonus. A single clear idea counted more than size.
8. **Sponsor fit.** All five run on Claude through GitLab Duo, and most say so in a "Why Claude" or "Powered by" line. Only TFGuardian also used Google Cloud (Cloud Run, keyless Workload Identity Federation, Google carbon data); none used Gemini. A sustainability angle was worth a lot: 5 of 13 awards went to it, while 40% of custom READMEs mentioned it.
9. **Publishing mattered.** Winners' agents and flows sit in the AI Catalog from the hackathon project, with many versions (TFGuardian 26, DELTA 10, CarbonLint and GreenPipe B 6). ShieldFlow AI, Ifrit Omega and the Autonomous DevSecOps platform published nothing from their projects. The hackathon CI published only `agents/*.yml` and `flows/*.yml`, so a flow kept in another folder was not published.
10. **Videos were rare even among winners.** Only BugFlow links one in its README (3 minutes, per the README). The others relied on screenshots, a live dashboard (TFGuardian) or an interactive deck (DELTA).

What this suggests for Life After Code (my reading): pick one post-merge moment, act through GitLab's own objects (issue, MR, comment), stop at a human decision, back every claim with a tool result or a labelled demo number, show the agent's own commits or comments in the repo, publish the flow to the AI Catalog early and version it, and keep the sustainability and Google Cloud angles real rather than decorative.
